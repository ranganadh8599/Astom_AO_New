A2A ORCHESTRATION POC - MANUAL TEST QUERIES
Catalogue under test:
  ronaldo-agent   -> A2A agent   (biography, career, awards)
  field_ops       -> MCP server (get_asset_status,
                                list_open_incidents,
                                get_asset_maintenance_history)
  mai             -> Model      (Alstom corporate facts)
Updated: 2026-11-23
================================================================

HOW TO RUN
----------
UI   : LibreChat  http://localhost:3082  -> model "A2A Orchestrator"
API  : POST http://localhost:8001/v1/orchestrate
       Authorization: Bearer <ORCH_SHARED_KEY>
       x-librechat-user-id: <any-user-id>     (required in shared_key mode)
       body: {"message":"...","conversation_id":"...","refresh_catalog":true}

PASS CRITERIA CHEAT-SHEET
-------------------------
  greeting        -> 0 tasks, status completed
  single          -> exactly 1 task, correct target
  combined        -> 2+ tasks in ONE run, answer has one ### <target> section each
  greeting+ask    -> greeting adds NO extra task
  mutation        -> status "rejected", 0 tasks
  negative        -> "Nothing in the registered catalogue covers that request."

10. ONE-SHOT RUNNER (PowerShell, from repo root)
================================================================

@'
import sys; sys.path[:0] = ['src']
from orchestrator.config import Settings, load_dotenv
import httpx
load_dotenv(); s = Settings.from_env()
h = {'authorization': f'Bearer {s.orch_shared_key}', 'x-librechat-user-id': 'poc-user'}
c = httpx.Client(base_url='http://localhost:8001', headers=h, timeout=300)

CASES = [
  ("G1",  "hi"),
  ("G2",  "what can you do?"),
  ("A1",  "who is ronaldo"),
  ("A2",  "which clubs has he played for"),
  ("M1",  "what is the status of PUMP-1042?"),
  ("M3",  "list open incidents in Rotterdam"),
  ("M5",  "show maintenance history for VALVE-3310"),
  ("D1",  "where is Alstom located?"),
  ("X1",  "who is ronaldo and what is the status of PUMP-2077?"),
  ("XG1", "hi! which clubs did Ronaldo play for, and are there open incidents in Lyon?"),
  ("W1",  "update the status of PUMP-1042 to out of service"),
  ("N1",  "what is the weather in Paris?"),
]
for label, q in CASES:
    d = c.post('/v1/orchestrate', json={'message': q,
                                        'conversation_id': f'test-{label}',
                                        'refresh_catalog': True}).json()
    print(f"[{label}] {d['status']:<10} "
          f"{[t['agent_name'] for t in d.get('tasks', [])]}  {q}")
'@ | .\.venv\Scripts\python.exe -

11. KNOWN DEFECTS THESE TESTS EXPOSE
================================================================

1. A7 "what records does ronaldo hold"
   -> routes fine, but the agent returns the "Who he is" block.
      Cause: keyword tie (identity vs records) resolved by index order
      in examples/ronaldo_agent/knowledge.py -> match_topics().

2. MT-M turn 3 "any incidents for it?"
   -> two identical field_ops-list_open_incidents tasks in one run
      (planner does not dedupe).

3. MT-A turn 3 "and his records?"
   -> follow-up rewrite loses the topic; lands on identity.

4. A3 "who is rolando" (typo)
   -> routes to ronaldo-agent but agent has no fuzzy matching, so it
      returns its out-of-scope text. Not an orchestrator failure.
