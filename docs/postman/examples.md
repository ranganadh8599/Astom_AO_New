# Postman examples — every request and its real response

Captured from a live run against this stack, so the JSON is what the services
actually return rather than what the docs imply. Generated by replaying the
collection; re-run it after changing an endpoint.

Requests that change state are **not** replayed — their examples are marked
`illustrative` and written by hand.

| Variable | Example |

## 12 · Register a LibreChat agent as a LiteLLM model

_Expose a LibreChat agent as a LiteLLM model so it is callable, and optionally routable, through the orchestrator.

**`POST /model/new` is NOT idempotent.** Each call adds another deployment of the same `model_name`, and LiteLLM load-balances across all of them. Two duplicates with different `api_base` values means roughly half of all calls fail with a connection error, which looks like flakiness rather than a configuration mistake. This folder therefore cleans up first and verifies after._

### POST Delete a model by model_id

`POST {{litellm}}/model/delete`

> Delete ONE deployment by its model id. This is the only way to remove a duplicate from `POST /model/new` — LiteLLM has no upsert and no bulk delete.
> 
> `{{model_id}}` is the `model_info.id` from `/model/info`, not the `model_name`. Deleting by name is not supported.
> 
> Status codes:
> - **200** `{"message": "Model: <id> deleted successfully"}`
> - **400** `Model with id=<id> not found in db` — already gone, or wrong id
> - **422** the body is missing `id`, or `id` is not a string
> 
> Deleting the last deployment of a `model_name` makes that model unavailable until it is registered again. If a `MODEL_TARGETS` entry points at it, the orchestrator's planner loses that target on the next turn.

**Request body**

```json
{
  "id": "{{model_id}}"
}
```

**Response — 200**

```json
{
  "message": "Model: {{model_id}} deleted successfully"
}
```
